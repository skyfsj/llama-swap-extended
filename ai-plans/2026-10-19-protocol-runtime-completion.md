## 实施顺序

1. 协议保真：原生字段及 opaque reasoning/compaction 原样保留；跨 provider 不泄漏原生状态；新增未知字段与不可移植能力明确处理。
2. Checkpoint：持久 portable transcript、工具历史、原生 opaque 状态与 provider/model/lineage；实现恢复、分支、checkpoint 与 provider 切换失效规则。
3. MCP 运行时：受配置约束的 stdio、Streamable HTTP 与旧 SSE 客户端，Tools/Resources/Prompts，权限、审批、结果、取消与生命周期；独立网关 MCP 服务端并接入现有模型工具循环。
4. 文件运行时：按内容寻址保存原始媒体，按身份授权；保留厂商引用及过期时间；按目标厂商上传并在引用过期后从原始内容恢复；不互换厂商 file IDs。
5. 执行规划：复用运行时能力发现，按目标返回保真、条件兼容、显式降级或拒绝；不能把模拟能力宣称为供应商原生能力。
6. 验收：跨轮 reasoning、并行工具、原生/托管 MCP、资源/提示、文件失效、状态分支、流中故障、缓存 usage、结构化输出和后台生命周期。
